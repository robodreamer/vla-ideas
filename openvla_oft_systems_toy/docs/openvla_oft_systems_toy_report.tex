\begin{abstract}
This note documents a compact deterministic toy experiment informed by OpenVLA-OFT. The source recipe combines parallel action decoding, action chunking, continuous actions, and L1 regression. The local experiment asks a narrower systems question: under delayed observations, how do serial-like action availability, parallel continuous chunks, and refresh cadence affect 2D tracking? A configured parallel chunk makes more actions available than the serial-like condition, but an open-loop suffix becomes stale. Refreshing halfway through the chunk gives the highest terminal-window success in this setup, while more frequent refresh gives the lowest mean tracking error but not the best terminal metric. This is an explanatory control result, not a reproduction or evaluation of OpenVLA-OFT.
\end{abstract}

\section{Motivation}

Action chunking changes more than the number of action values a policy emits. A parallel chunk can make a future sequence available at once, but the latter part of that sequence was produced from an observation that may already be stale. In a closed-loop controller, the choice of when to replace the unfinished suffix can therefore trade action availability against stale-feedback error and command discontinuities.

OpenVLA-OFT provides a source-grounded motivation for considering this output-side design. Kim, Finn, and Liang describe optimized VLA fine-tuning with parallel decoding, continuous action chunks, and L1 regression \cite{oftpaper,oftsite,oftcode}. This toy does not implement that training recipe. Instead, it isolates the timing question with an analytical continuous controller, so the serial-like versus parallel interface and the refresh schedule are visible without attributing a local result to the published method.

\section{Toy Setup}

The script \texttt{run\_openvla\_oft\_systems\_toy.py} simulates a two-dimensional point mass for 7.2~s at a 40~ms control tick. It tracks a bounded moving target from observations delayed by 160~ms. Every ninth tick, a seeded Gaussian velocity gust with standard deviation 0.045 per axis perturbs the state. The target phase, start state, and gust sequence are deterministic for a trial seed.

The desired continuous velocity is a clipped proportional--derivative rule,
\[
  a_t =
  \operatorname{clip}\!\left(2.4(g_t-p_t)-0.48v_t,\,-1.15,\,1.15\right).
\]
The parallel generator rolls this rule forward from the delayed observation to produce an eight-action chunk. The simulated plant then diverges from that imagined rollout because of delayed feedback and gusts.

Four timing conditions are evaluated:
\begin{enumerate}[leftmargin=1.5em]
  \item \textbf{Serial autoregressive-like:} one continuous action is available after a configured 55~ms decision delay, and the preceding action is held while the synthetic decoder is busy.
  \item \textbf{Parallel open loop:} eight continuous actions are available after a configured 60~ms decision delay and are consumed before replanning.
  \item \textbf{Parallel refresh-4:} the same parallel chunk is replaced after four executed actions.
  \item \textbf{Parallel refresh-2:} the same parallel chunk is replaced after two executed actions.
\end{enumerate}

The reported action-output throughput counts all generated actions. It therefore counts discarded suffixes when a parallel chunk is replaced early; it measures simulated output work/availability, not useful actions or the fixed 25~Hz plant tick.

\section{Metrics}

The Monte Carlo sweep reports:
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{simulated decision latency:} the configured time before an action or chunk is available, not wall-clock profiling;
  \item \textbf{action-output throughput:} generated action values per simulated rollout second;
  \item \textbf{mean and final tracking error:} Euclidean distance to the moving target, averaged over time or evaluated at the final tick;
  \item \textbf{terminal-window success:} one when the final 20-tick mean tracking error is below 0.16;
  \item \textbf{jerk proxy:} the time-average norm of the second finite difference of emitted commands. This is a descriptive smoothness measure, not an actuator limit.
\end{itemize}

\section{Interpretation}

The serial-like condition has the lowest action availability because it serializes decisions and holds commands during its configured delay. A full parallel chunk restores plant-rate availability but has the weakest terminal-window success among the parallel conditions: an eight-step suffix becomes increasingly unsuitable as the delayed state and gusts diverge from its imagined rollout.

Refreshing halfway through the chunk has the highest success in this run (33.3\%) and improves mean error to 0.316. Refreshing every two actions has the smallest mean error (0.311), but success returns to 28.1\% and the jerk proxy rises relative to open loop. This is the local trade-off: frequent refresh reduces stale-chunk exposure and increases generated-output work, yet it repeatedly re-anchors the controller to four-tick-old feedback and creates more command boundaries. Mean tracking, terminal-window occupancy, and smoothness need not select the same refresh cadence.

\section{Limitations and Follow-ups}

This is not a faithful OpenVLA-OFT implementation. It omits OpenVLA weights, image observations, language grounding, LoRA, L1 optimization, LIBERO/ALOHA data, robot dynamics, real inference timing, and a capacity-matched autoregressive VLA. The controller, plant, target, and chunk rollout share an intentionally simple analytical design. The delays are configured rather than measured, the output-rate accounting favors early refresh by counting discarded actions, and the terminal threshold is an arbitrary toy metric.

The numerical differences should therefore be read as an explanatory result rather than evidence for a universal refresh optimum or an OpenVLA-OFT mechanism. Useful follow-ups would be:
\begin{enumerate}[leftmargin=1.5em]
  \item add paired per-trial exports and bootstrap intervals while sweeping observation delay, chunk horizon, and gust magnitude;
  \item replace fixed synthetic latency with sampled model/service latency, queueing, deadlines, and a late-chunk fallback, while accounting separately for useful and discarded actions;
  \item add model mismatch between chunk imagination and plant, then compare ordinary refresh with a state-predictive or latency-compensating controller;
  \item move to a constrained higher-dimensional task with a learned continuous chunk policy, randomized observations/instructions, and a capacity-matched serial baseline.
\end{enumerate}
